## 2025-05-18 - Missing rel="noopener noreferrer" on target="_blank" links
**Vulnerability:** External links (`<a target="_blank">`) without `rel="noopener noreferrer"` can allow the newly opened tab to manipulate the `window.opener` object of the referring page. This is a vector for reverse tabnabbing attacks, where the new page can navigate the original page to a malicious site.
**Learning:** This is a common issue with `target="_blank"` links. I should always verify if they have the proper `rel="noopener noreferrer"` attribute, both in static HTML and dynamically generated HTML. Note that `rel="noopener"` is usually sufficient in modern browsers, but `rel="noopener noreferrer"` is strictly best practice. The memory actually instructed: "Security Standard: All external links utilizing `target="_blank"` must explicitly include `rel="noopener noreferrer"` to prevent reverse tabnabbing via `window.opener`. This applies to statically written HTML as well as dynamically injected HTML in template literals."
**Prevention:** Add a check for `target="_blank"` in the linter or CI pipeline to ensure that `rel="noopener noreferrer"` is also present.
